# Public GitHub QA

Use this quick check after exporting the public GitHub cut.

## Visual checks

- Open the public repository index.
- Open the public release boundary.
- Open the public release checklist.
- Open the public release map.
- Open the GitHub publication guide.
- Confirm the website hero exposes the public repository index as an immediate
  entry point.
- Confirm the website footer links still point to the public docs.
- Confirm the website evidence trail links still point to the evidence docs.
- Confirm the website exposes the evaluation bundle as the quickest public start.
- Confirm the website exposes the evaluation runbook as the quickest proof order.

## Export checks

- Confirm the export contains only the approved public files.
- Confirm the export contains `README.md`, the public policies, and the public docs.
- Confirm the export contains the public-safe package README and file lists.
- Confirm the export contains the short signal-chain result snapshot.
- Confirm the export does not contain `main/`, `components/`, or `examples/linux/`.

## Content checks

- Confirm the public cut explains what is public, partner-only, and private.
- Confirm the public cut does not expose transport internals or private reference tools.
- Confirm the signal-chain evidence and result snapshot agree on the same hashes.
- Confirm the evidence trail presents the template, index, example, and result
  in that order.
- Confirm the export contains the Linux reference evidence page and the
  public index links to it.
- Confirm the evaluation bundle points at the product brief, index, example,
  result, and proof record.
- Confirm the evaluation runbook points at the bundle, proof trail, boundary,
  and final hash evidence.
